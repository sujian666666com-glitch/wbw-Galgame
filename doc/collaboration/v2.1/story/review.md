  - 理想版按契约写成同车：两人并排在同一节车厢，许晚晴仍用手机发“到了以后，发一张你窗外的照片”，以“先练习异地沟通”解释这个玩笑；王不稳改为“到站以后，我想认真和你约会”，许晚晴回答先看房子、约会排在后面，保留短信玩笑。
  - 普通版按契约写成异地：王不稳独自在车厢，收到同样消息，只回“下次见面，我请你吃饭。到时候再听你说说最近的事”，她回“好。别挑太贵的店。”不确认约会关系，保留克制和可持续联系。

### 2.4 续篇章内信任阈值

四位角色的章内亲密表达从春之章起以对应信任 `>= 3` 为条件；初遇章 Dana 尚为 0，不设信任分支。低值保留角色性格和职业关系，不确认恋情：

- Dana：初遇时 `dana_affection` 仍为 0，因此初遇段不设 `>= 3` 分支，也不保留“留午饭位置”的亲近版；Dana 仍会介绍食堂和靠窗位置，但明确不替王不稳安排生活，尊重距离。春庭段起才以 `dana_affection >= 3` 区分握手/单独看花与共同核对记录/来帮忙种花的克制版。
  - 接入顺序说明：原稿把“春庭的约定”附在春之章末尾；蓝本建议把它放在 Luna 说完“可以。但到了现场，必须遵守我的安全方案。”之后、“夜色落下前，一行人向海边灯塔出发。”之前。这样“危机解除的傍晚”发生在出发前，避免产品流程出现回叙；位置仍在 `jump sequel_chapter_03_summer` 之前。
- Luna：灯塔段先按 `sequel_luna_observation_outcome` 分支回忆动作，再按 `luna_affection >= 3` 决定是否说“我也很高兴你回来”。低值只保留工作评价与次日校准。
- Irene：秋日段插在取得秋之碎片之后、“最后一页／Ruby 只剩一夜”警告之前，作为紧迫转折前的一小段休息；低值仍让她说出“我想告诉你”，但不靠肩；以共同归档、留一副手套收束，不再说“明天慢慢整理”。
- Ruby：冬夜段高值摘耳坠、脸颊吻后把耳坠递还并戴好，保证终章广播和结局立绘一致；低值保留“我不是因为能听见镜的声音才值得留下”，但把“被人牵着手走回家”改为“被人记住”，不摘耳坠、不接吻，最后只把耳坠扶正。
- 终章“最后的独处”：四位角色各自按对应信任分支。高值使用原稿的“单独看花”“一起确认日出”“听我说废话”“每年写信”；低值改为花园帮忙、按流程复核、保留私人时间、保存可查日期的来信，均不确认恋情。

### 2.5 夏章动作回忆的特殊处理

`v21_sequel_chapter_03_summer` 的第一段回忆只读取 `sequel_luna_observation_outcome`，不以 Luna 好感推断玩家当时做了什么：

- `paper_tape`：六十秒内带回二号点纸带，Luna 认可“主动回来”。
- `aborted`：曾离开安全绳，但随后服从现场方案；Luna 认可“判断失误后服从方案”。
- `evacuated`：撤离优先、放弃现场数据；Luna 认可“人员撤离放在设备之前”。
- `unknown`（旧档或未写入）：中性版，只评价“会听我把话说完”，不虚构具体动作。

契约要求的 `paper_tape` / `aborted` / `evacuated` 三个值由技术负责人在夏章 M05 三个选项处写入，只记录事实，不改变原奖励。`default sequel_luna_observation_outcome = "unknown"` 需由技术负责人加入状态文件。

### 2.6 续篇结局后日谈

- Dana、Luna、Irene、Ruby 四个结局的入口本身已要求对应信任 `>= 3`，因此结局后日谈不再重复设低信任分支，避免出现“未确认恋情却进入恋爱结局”的不可达矛盾。低信任克制版集中在章内片段。
- Ruby 共通脸颊吻只出现在冬之章 `ruby_affection >= 3` 的分支，使用立绘 `ruby resolute`/`ruby normal` 与文字，不使用 CG；吻后 Ruby 把耳坠接回戴好，与终章“耳坠里保存的声音，也接入了广播”及结局立绘一致。
- Ruby 低信任分支只说“没有摘下耳坠”，结尾统一为“把耳坠扶正”，不再出现“重新戴好”的自相矛盾。
- 专属 CG `cg v21_ruby_ending_kiss` 只用于 `v21_sequel_ending_ruby` 的唇吻，不用于共通章内片段。
- 返回现实后日谈不设信任门槛；真结局后日谈只在真结局路线播放。

- 邮件、银铃、镜面提示都不单独构成通行证；它们只是伏笔与情绪回收。真结局仍需玩家在终章主动选择共同记忆。

## 6. 技术转录注意事项

1. **调用方式**：23 个 label 都以 `return` 结束，技术负责人应在 `manifest.json` 的 placement 位置使用 `call`，不要用 `jump`。用 `jump` 会导致后日谈结束后无法回到原流程。
2. **禁止内容**：蓝本没有 `menu`、没有 `$` 赋值、没有 `persistent` 写入。转录时不要为了“补奖励”加入数值变化；所有数值仍由原脚本负责。
3. **新增状态**：技术负责人需在 `game/core/state.rpy` 加入 `default sequel_luna_observation_outcome = "unknown"`，并在夏章 M05 三个选项分别写入：
   - 执行 Luna 分组方案、带回二号点纸带 → `"paper_tape"`；
   - 离开安全绳、被迫退回 → `"aborted"`；
   - 立即撤离、放弃现场数据 → `"evacuated"`。
   只记录事实，不改变原奖励。
4. **图像 ID**：新增资源严格使用以下九个 ID，不得改写：
   - 表情：`dana worried`、`luna soft`、`irene shaken`、`irene relieved`、`ruby resolute`；
   - 背景：`bg v21_train_interior_dusk`、`bg v21_old_house_mirror`；
   - CG：`cg v21_xuwanqing_rain_close`、`cg v21_ruby_ending_kiss`。
   既有表情只使用王不稳 `normal/confident`、许晚晴 `normal/happy/serious/worried/angry/surprised`、四位续篇角色 `normal`。蓝本没有使用任何未列出的新表情。
5. **CG 使用边界**：
   - `cg v21_xuwanqing_rain_close` 只在 `affection >= 8` 的雨伞分支显示。
   - `cg v21_ruby_ending_kiss` 只在 `v21_sequel_ending_ruby` 显示。
   - 冬之章共通脸颊吻只用立绘与文字，不调用任何 CG。
6. **镜中文字**：`bg v21_old_house_mirror` 应为无字背景；镜面文字由脚本旁白或代码叠加呈现，不得烘焙进图片。
7. **场景恢复**：各 label 自行设置 `scene`/`show`。`call` 返回后，原脚本的后续段落会重新设置场景；若技术在同一场景内连续调用多个 label，需确认 `hide` 状态符合预期。
